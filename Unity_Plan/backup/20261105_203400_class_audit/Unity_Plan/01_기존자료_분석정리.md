## 1. 현재 프로젝트의 상태

이 프로젝트는 소울라이크 액션 RPG의 전투 밸런스를 검증하는 도구를 목표로 한다. 플레이어 조작 차이를 확률형 AI 행동으로 모델링하고, 다대다 전투를 여러 번 실행하여 승률과 전투 시간을 비교하는 것이 핵심이다. 단순한 공격력 비교에서 이동·회피·가드·연계 공격이 있는 전투 관찰 도구로 발전시키는 방향이 적합하다.

현재 폴더에는 **엑셀 기획·데이터·기존 결과가 충분히 있으나, 기존 전투 엔진의 파이썬 소스는 확인되지 않는다.** 따라서 현재 자료만으로는 완성된 Python 전투 엔진을 C#으로 일대일 번역할 수 없다. 데이터와 규칙을 재사용하고 실행 엔진을 새로 구현하는 계획이다. 다른 위치에 엔진 원본이 있다면 추후 동작 비교 기준으로 추가할 수 있다.

| 구분 | 확인한 상태 | Unity에서의 활용 |
| --- | --- | --- |
| 전투 기획 | 순서도, 피해량, 자원, 강인도, 상태이상 정의 | 전투 규칙의 근거 |
| 캐릭터와 장비 | 성장 계산표, 최종 스탯, 장비와 강화 데이터 | 초기에는 계산된 최종 스탯을 가져오기 |
| 스킬과 AI | 무브셋, 스킬 시간, 조건식, 페이즈, 행동표 | 데이터 기반 실행 |
| 기존 전투 결과 | 승패 집계와 30f 상세 로그 저장 | 로그 형식 참고 및 제한적인 회귀 비교 |
| Python 소스 | 엑셀 파일 저장 예제와 pandas import | 데이터 변환 도구를 새로 확장할 출발점 |
| Unity | 프로젝트 파일·장면·C# 소스 없음 | 신규 프로젝트 구성 필요 |

### 조사 범위와 한계

- 엑셀 28개, 전체 247개 시트(숨김 포함)의 저장된 셀 값·수식 레코드·오류를 추출하여 구조를 점검했다. 값 또는 수식이 있는 셀 레코드는 총 3,676,246개다. 반복된 계산표와 로그는 전체 추출 후 구조·오류 집계와 대표 행을 중심으로 검토했다. 모든 수식을 독립적으로 재계산한 것은 아니다.
- 엑셀에 삽입된 이미지 12종(중복 제외)의 순서도와 참고 이미지를 확인했다. 텍스트 설명만 읽으면 빠지는 자원 사용·가드·피해량 분기가 여기에 있다.
- 프로젝트 Python 2개, 텍스트 기획 2개, requirements 및 개발 설정을 확인했다. `venv`의 외부 패키지, `.git` 내부 이력·바이너리는 게임 기획/구현 소스 범위에서 제외했다.
- `.xlsm` 15개의 VBA 소스 스트림을 추출해 정적으로 읽었다. 공통 로드 매크로와 문서/시트 클래스 선언이 확인됐으며, 추출한 소스에서 전투 실행·JSON 내보내기 구현은 확인되지 않았다. **매크로 실행과 Excel 재계산 검증은 하지 않았다.** 원본 파일은 변경하지 않았다.
- 아래 오류 수는 파일에 저장된 오류 값이다. Excel에서 새로 계산했을 때의 결과와 동일하다고 보장하지 않는다.

### 2.5 VBA 로드 매크로

매크로 포함 파일 15개에서 공통 `Sheet1` 소스의 `LoadAll`, `LoadCurrentRow`, `LoadOneRow`, `GetOrCreateSheet`, `ValOrOne`을 확인했다. 전체 행 또는 현재 행을 선택해 `~TableLoad` 형태의 설정을 읽고, 외부 통합문서를 읽기 전용으로 열어 지정 시트의 UsedRange를 대상 시트에 **값으로 복사**한다. 경로가 비어 있으면 현재 통합문서 폴더를 사용하고, 대상 시트를 비운 뒤 붙여넣으며 로드 시각/오류를 기록한다.

이는 참조 시트가 원본과 실시간으로 연결된 데이터가 아니라 마지막 로드 시점의 사본일 수 있다는 근거다. 보이는 수식이나 오류가 없는 참조 시트라도 최신 데이터라고 단정할 수 없다. 또한 시작 열 처리 함수는 숫자가 아니면 1을 반환하므로 설정의 `A`는 결과적으로 첫 열이 되지만 다른 문자 열을 일반적으로 변환하는 코드는 아니다. Unity 변환기에서는 열 이름을 명시적으로 해석한다.

## 3. 기존 전투 규칙

### 3.1 밸런스 방향과 성장

소울라이크에 익숙한 라이트 유저를 기준으로, 반응속도보다 반복 학습으로 극복 가능한 난이도를 지향한다. 전체 보스 클리어 플레이타임 기준은 16시간이다. 초반 성장 체감을 크게 하고 필드 난이도에 강약을 둔다. 이 목표는 전투 엔진의 상수가 아니라 결과 분석의 기준으로 둔다.

1차 스탯은 VIGOR, MIND, ENDURANCE, STRENGTH, DEXTERITY, INTELLIGENCE, FAITH의 7종이다. 기획상 20/40/60에서 상승 효율이 감소한다. HP·FP·스태미나, 회복량, 운반력, 공격/감소율, 강인도, 상태이상 저항 등으로 연결된다. 무기는 무게·모션 길이에 맞춰 피해량을 조정하고 S~D 보정 등급을 사용한다. 초기 Unity에서는 이 성장 공식을 전부 재작성하기보다 **계산 완료된 스탯을 입력**받는 편이 검증 범위를 줄인다.

### 3.2 전투 진행과 자원

출처: `1.ARPG_전투공식.xlsx` → `전투 프로세스!F13:F18` 및 스킬 자원 소모 순서도.

1. 행동/스킬 선택.
2. 사용 조건 판정과 자원 차감.
3. 정해진 시점에 공격 판정 활성화.
4. 대상의 팀·무적·패리·가드·일반 상태를 판정.
5. HP 피해, 강인도 피해, 상태이상 누적 적용.
6. 버프/디버프와 사망/종료 처리.

초기 원본 순서도는 스태미나가 **0보다 크면 시도를 허용**하고 소모 후 음수를 0으로 보정하는 형태였으나, 이번 사용자 확정 규칙이 이를 대체한다. **스태미나 소모 행동은 현재값이 1 이상일 때 시작하며, 비용보다 적더라도 전체 비용을 차감해 음수를 유지한다. 다시 1 이상이 될 때까지 스태미나 소모 행동을 시작하지 못한다.** 예: 20에서 비용 50 행동을 실행하면 -30, 회복 후 0.5에서도 불가, 1부터 가능. 비용 0 행동에 이 제한을 일괄 적용하지 않는다. ‘비용 이상 있어야 사용’과 다르므로 그대로 구별해야 한다. 이전 그림에는 HP 소모·사망 분기와 FP 부족 실패 모션이 있지만, 현재는 **자원을 먼저 검사하고 가능한 행동을 선택**하는 규칙을 적용한다. `현재 HP - HP 비용 >= 1` 및 `현재 FP - FP 비용 >= 0`을 모두 만족해야 사용 가능하며, 실패하면 HP·FP·스태미나를 모두 차감하지 않는다. HP 50/FP 50에서 비용 HP 49/FP 50이면 사용 후 HP 1/FP 0으로 가능하다. HP 비용 50 또는 FP 비용 51이면 불가능하다. 스태미나는 소모 후 음수를 허용하므로 별도 승인 조건을 쓴다.

### 3.3 피해와 방어

- 물리 계열(일반 물리/참격/관통/타격/사격)과 마력·불·물·벼락·신성 속성을 구별한다.
- 무기 피해는 해당 공격력과 모션 배율, 공격력 증가, 거리 감쇄, 차지, 난수, 그로기 보정, 대상 감소율 순으로 구성된다. 촉매 스킬은 마술/기도 보정을 사용하는 별도 경로다.
- 거리 감쇄 예제는 로그함수와 감쇄 상한 0.95, 소수 둘째 자리 버림을 사용한다. 차지 예제는 ms 단위를 사용한다. 이 반올림 위치도 공식의 일부로 관리한다.
- 가드 시 HP 피해와 스태미나 피해를 분리한다. 최신 전투공식의 충돌 그림은 `피해량 × 10 / 가드 강도`, 이전 밸런스개요 그림은 `피해량 × 100 / 가드 강도`다. **이번 사용자 확인으로 계수 10을 확정**했다. 계수 100은 이전 자료의 기록으로만 남긴다.
- 패리는 공격자 패리 내성을 차감하고 0 도달 시 기절·초기화하는 흐름이다. 뒤잡기/패리 후 일격 활성화 여부와는 별개다.
- 강인도는 피해 후 5초 동안 회복이 멈추고 다시 피격되면 대기 시간이 갱신된다(`전투 프로세스!I363:I364`).

`4.전투시뮬레이터.xlsx`의 `대미지메이커!H2:V2`에는 검사 37레벨 약공격 계산 예시가 있다. 공격력 약 91.002321, 난수 기대 배율 1.0005, 감소율 0.33에서 최종 약 61.002041이 기록되어 있다. 이는 **저장된 기대값 예시**이며 임의 시드 전투에서 매번 61이 나와야 한다는 뜻은 아니다.

### 3.4 상태이상과 효과

| 종류 | 기획 내용 |
| --- | --- |
| 기절 | 90f 행동 불가, 플레이어 기반 캐릭터의 잡기 가능 |

지속형 상태이상은 기존의 효과 중 동일 상태이상 면역 규칙을 유지한다. 이번 확정 사항은 다음과 같다. 누적 게이지는 쌓인 직후부터 대기시간 없이 초당 5씩 감소한다(0 미만으로 내려가지 않음). 중독 첫 피해는 발동 1초 뒤다. 상처는 즉시 피해 처리 직후 게이지를 다시 쌓을 수 있으며 별도 면역 대기시간을 두지 않는다. 빙결은 이동·공격·구르기에만 적용한다. 기획은 스킬당 최대 3개 버프/디버프를 설명하지만 현재 SKILL 열은 한 묶음의 Additional_Effect 구조이므로 배열화가 필요하다.

### 3.5 AI와 무브셋

현재 `AI.xlsx/README!B4`, `B7:B19`의 규칙을 기준 후보로 삼는다.

- 전투는 30Hz, AI 판단은 10Hz이므로 3 전투 tick마다 판단하는 방식으로 연결 가능하다.
- AI_ID와 현재 페이즈 또는 공통 페이즈(0)를 골라 Eval_Order 오름차순 평가. 조건 1 AND 조건 2, 확률, 쿨다운을 통과한 첫 행동 실행.
- Chance_Pct는 0~100이며 가중치가 아니다. 조건이 같은 50% 행 두 개라면 두 번째의 실제 선택 확률은 앞 행 실패를 포함해 25%가 된다.
- 조건별 마지막 100% 폴백이 필요하다. 스킬 사용 불가 시 다음 행을 볼지, 대기할지 실행 계약을 명시해야 한다.
- PC는 EX_PC.AI_ID 직접 연결. 몬스터의 AI_10101 같은 값은 현재 AI 표에 직접 연결하지 않고 이름→AI_MAP→프로필로 바꾸며 종족 폴백이 있다.
- INPUT 행동은 Moveset_ID + Input_Slot + 이전 노드로 Skill_Id를 찾는다. BUILTIN은 이동·대기·회피다.
- 거리 대역 2.5m/6m, 인지 18m, 해제 30m, 최근접 타겟과 20% 히스테리시스가 README에 있다. 해당 값을 구현한다는 `config.py`는 현재 폴더에 없다.
- Accuracy 미사용이 명시되어 있다. 무적·범위 판정과 별도로 명중 확률을 새로 적용하면 현재 기획을 바꾸게 된다.
- BACKSTAB/RIPOSTE는 비활성, 물약은 미결이다. ‘테이블에 이름이 있음’과 ‘기능이 활성화됨’을 구별한다.

### 3.6 기존 결과 로그

`4.전투시뮬레이터.xlsx/전투 시뮬레이터 상세결과`에는 회차, 프레임(30f), 캐릭터 이름, HP, 행동, 대상, 피해량, 시간, 팀, Skill ID, 스태미나, 강인도, 상태이상, 거리, 대상 잔여 HP, 비고가 있다. FP와 개체 고유 ID는 새 로그에 추가해야 한다. 같은 이름의 캐릭터가 여러 명 있어 이름만으로 식별하면 안 된다.

집계 시트에는 100회 설정, 아군 승리 0, 적군 승리 65, 300초 무승부 사례가 보인다. 설정 횟수와 실제 완료 횟수, 무승부·중단을 분리해 표시하는 것이 좋다. 원본 엔진·시드·버전이 없어 기존 결과와 완전 일치하는 재현은 아직 불가능하다.

## 5. 이번 전환의 범위

요청된 필수 기능은 캡슐·기본 도형 캐릭터, Unity Console 로그, CSV 저장, 머리 위 HP/FP/스태미나 바, 관찰 배속, 비시각 고속 반복 실행이다. 기본 전제는 **AI 자동 전투를 관찰하고 분석하는 Windows용 도구**다. 직접 조작하는 액션 게임, 복잡한 지형, 네트워크 동기화는 후속 범위로 남긴다. 이 전제는 원래 게임의 최종 범위를 제한하지 않는다.

핵심 원칙은 전투 상태의 소유자를 하나로 두는 것이다. C# 전투 코어가 위치·자원·피해·난수를 계산하고 Unity는 그 상태를 표시한다. 그래야 1배속, 8배속, 비시각 실행의 결과를 같은 조건에서 비교할 수 있다.

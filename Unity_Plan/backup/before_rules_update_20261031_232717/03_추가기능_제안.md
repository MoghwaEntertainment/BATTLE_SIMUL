# 추가 기능 제안과 우선순위

작성일: 2026-10-31. 사용자가 요청한 도형 표시, Console/CSV, 자원 바, 배속, 비시각 실행은 필수 범위다. 아래 항목은 그 기능을 신뢰할 수 있는 밸런스 도구로 만드는 추가 제안이다.

## 1. 첫 버전에 함께 넣을 기능

| 우선순위 | 기능 | 필요한 이유 | 최소 구현 / 완료 기준 |
| --- | --- | --- | --- |
| P0 | 데이터 사전 검증 | 이름 오류, 단위 혼재, 누락된 스킬을 조용히 무시하면 잘못된 밸런스 판단 | 파일·시트·셀·ID와 원인을 표시. 필수 전투 참조 오류는 실행 차단 |
| P0 | 시드 고정과 같은 조건 재실행 | 난수 때문에 수정 효과와 우연을 구별하기 어려움 | seed·scenario·dataHash·rulesVersion 기록. 같은 빌드에서 재실행 이벤트 일치 |
| P0 | 전투 시나리오 저장 | 종류·수량·배치를 매번 다시 입력하는 비용 감소 | 팀, 개체, 배치, 제한 시간, 시드, 반복 수를 JSON 프리셋으로 저장 |
| P0 | 일시정지·1 tick 진행·재시작 | 회피와 타격이 같은 순간 발생했을 때 원인 확인 | 1 tick=1/30초, 재시작은 처음 상태와 동일 시드로 복원 |
| P0 | 명확한 종료 사유 | 기존 결과에도 300초 무승부 존재 | 승리/패배/동시 전멸/시간초과/사용자 중단/오류 구분 |
| P0 | 반복 실행 진행률·취소 | 수천 회 실행 중 앱이 멈춘 것으로 보이지 않게 함 | 완료/요청 횟수, 처리량, 취소 버튼. 완료한 결과와 미완료 상태 보존 |
| P0 | 로그 수준과 필터 | 상세 로그가 비시각 실행의 주된 병목이 될 수 있음 | Console·CSV·화면 필터 분리. 필터가 결과 집계에 영향 없음 |
| P0 | 개체 선택 정보창 | 머리 위 3개 바만으로는 행동·스킬·강인도 확인이 어려움 | 개체 ID, 대상, 현재/최대 자원, 행동 단계, AI 행, 상태이상 표시 |

P0라고 모든 편의 UI를 정교하게 만들 필요는 없다. 설정 파일과 간단한 패널로 시작해도 된다. 특히 데이터 검증·재현성·종료 사유는 시각 효과보다 먼저 필요하다.

## 2. 전투 관찰과 디버깅 개선

| 우선순위 | 기능 | 최소 구현 |
| --- | --- | --- |
| P1 | 사거리·공격 범위·추적 방향 표시 | 선택 개체만 원/부채꼴/박스로 표시. 코어와 같은 판정 파라미터 사용 |
| P1 | 선딜·타격·후딜·무적 색상 | 선딜 노랑, 타격 빨강, 무적 청록 등 상태 범례 제공 |
| P1 | 피해량 계산 상세 보기 | 기본 공격력→모션→보정→방어→최종값, 가드 자원 피해를 함께 표시 |
| P1 | AI 선택 이유 표시 | 선택된 Behavior_Index, 조건값, 확률, 쿨다운, 거절 사유 |
| P1 | 카메라 이동·확대·개체 추적 | 고정 사선 시점에서 시작하고 선택 개체 추적 추가 |
| P1 | 행동 이벤트 위치로 이동 | 로그 선택 시 해당 개체 강조. 시간 이동은 실제 리플레이 기능 도입 후 지원 |
| P2 | 전투 리플레이 | 시나리오+시드+버전으로 재실행. 임의 시점 탐색은 주기적 스냅샷과 난수 상태 저장 추가 |

리플레이를 단순 CSV 재생과 혼동하지 않는다. 모든 위치·행동 상태가 저장되지 않은 로그만으로 정확한 전투 장면을 복원하기 어렵다. 첫 단계에서는 실패한 회차를 같은 조건으로 다시 실행하는 기능이면 충분하다.

## 3. 밸런스 분석 기능

| 우선순위 | 기능 | 분석할 값 |
| --- | --- | --- |
| P1 | 반복 결과 요약 | 승률, 무승부율, 평균/중앙 전투 시간, 생존 인원, 잔여 자원 |
| P1 | 원인별 집계 | 스킬별 피해·사용/적중 횟수, 가드·회피, 자원 부족 횟수, 행동별 체류 시간 |
| P1 | A/B 비교 | 같은 시드 목록으로 변경 전후 승률·시간·피해를 비교 |
| P2 | 조건 일괄 실험 | 레벨×장비×적 수×AI 성향 조합을 묶음 실행 |
| P2 | 목표 시간 이탈 표시 | 무기/적 유형별 목표 처치시간과 허용 범위 비교 |
| P2 | 신뢰구간과 결과 분포 | 승률의 표본 불확실성, 전투 시간의 분산·분위수 |

승률은 기본적으로 `아군 승리 / 완료된 유효 전투 수`로 제안한다. 무승부·시간초과는 분모에 포함하고 사용자 중단·데이터 오류는 제외하며 각각 횟수를 표시한다. ‘승패가 난 전투 중 승률’은 보조 지표로 따로 표시한다. 기존 결과의 100회 설정과 적 승리 65회만 보고 나머지를 모두 실패나 누락으로 판단하지 않는다.

최소 분석 파일은 회차별 한 행인 `results.csv`와 전체 집계인 `summary.csv`다. 이벤트 상세 CSV는 선택 출력한다. DPS는 전투 전체 시간 기준인지 실제 공격 가능 시간 기준인지 이름에 명시한다. 100% 승률이 나와도 단 몇 회만 돌렸다면 확정적 결론으로 표시하지 않는다.

## 4. 데이터 부족 때문에 별도 기획이 필요한 기능

| 기능 | 현재 빈틈 | 권장 순서 |
| --- | --- | --- |
| 스태미나 관리 | 스킬 비용 0과 몬스터 자원 0의 의미 미확정 | UI를 먼저 가짜로 줄이지 말고 선택된 스킬의 실제 정책부터 정의 |
| 원거리 투사체 | ID는 있으나 마스터와 이동/충돌 규칙 부족 | 초기는 명시적 즉발 모드 또는 지원 제외. 이후 속도·수명·반경·관통 정의 |
| 버프·디버프 | 최대 3개라는 기획과 1묶음 데이터 차이 | 효과 배열, 중첩, 갱신, 면역 우선순위 정의 |
| 물약 | AI에서 미결·비활성 | 사용 횟수·선딜·회복 시점·취소·회복 후딜 정의 후 활성화 |
| 보스 패턴 | 수기 조건과 타격 종료 시점이 현 스킬 형식에 완전히 들어가지 않음 | 전용 패턴/타격 구간 정의를 추가한 뒤 대표 보스 한 종 검증 |
| 악세사리·세트효과 | 현재 메모에 누락으로 기록 | 최종 스탯 입력 MVP 이후 장비 계산 확장 때 반영 |

## 5. 당장 미뤄도 되는 것

고품질 캐릭터 모델과 모션, 네트워크 대전, 복잡한 지형과 NavMesh, DOTS 전면 도입, 인게임 스킬 편집기, 웹 배포, 자동 밸런스 최적화는 첫 버전의 필수가 아니다. 캡슐 전투에서도 규칙과 데이터가 맞는지 충분히 검증할 수 있다. 성능 목표는 대표 다대다 시나리오로 측정한 뒤 정하고 ‘몇 배 빨라진다’는 수치는 구현 전 확정하지 않는다.

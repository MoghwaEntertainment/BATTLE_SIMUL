## 2. 데이터 변환에서 확인된 사항(현재 테이블 기준)

- 배포 차단 오류 0, 레코드 비활성 11, 경고 8. dataHash `92c8fceb13c30d43`.
- **SKILL 의 SWORD 스킬 24행(A166~A189)이 A3~A26 과 완전히 같은 중복**이다. 첫 행만 사용한다. 기존 문서의 '플레이어 스킬 187개'는 이 중복을 포함한 수이며 고유 스킬은 163개.
- **Hit_Count 가 2~5 인데 Hit_Time·Motion_Value 가 1개뿐인 무기 기술 11개**(SWORD_WEAPON_ART_002/007, HAMMER_004/006, SPEAR_002/008, BOW_002/004/009, STAFF_002/004). 04 문서 11.2 의 '다단히트 행 없음'과 달리 실제로 존재한다. 확정 규칙대로 임의 분할/복제하지 않고 비활성 처리했다. 현재 검사(SWORD_001 무브셋)는 WEAPON_ART_001 만 쓰므로 영향 없음.
- TALISMAN_WEAPON_ART_006~008 의 Skill_Type 이 숫자(1/2)로 저장 → 템플릿 enum 순서로 BUFF/DEBUFF 매핑. Buff_ID 가 0 이라 효과 없음.
- EX_PC 의 ~Name 630개가 #N/A → 표시 이름은 ~구분용, 전투 ID 는 Index.
- 몬스터 WEAPON_ART 96행에 FP 비용 8 이 남아 있음 → 몬스터 자원 미관리 설정으로 실행 시 무시.

## 3. 검증

- 이 작업 환경에는 C# 컴파일러/Unity 가 없어 **Unity 에서의 컴파일과 실행은 아직 확인되지 않았다.** 프로젝트를 열었을 때 Console 에 컴파일 오류가 있으면 그 내용으로 수정이 필요하다.
- 코어 알고리즘은 같은 구조의 Python 미러로 실제 데이터 5개 시나리오를 실행해 전투가 정상 종료되는 것(승리/시간초과)과 타격 tick(300/600/900ms → 8/17/26), 게이지 감소(60→55), 다단히트 100/150/200 을 확인했다.
- Unity 안에서는 `ARPG > 3. Self Test 실행` 또는 화면의 `Self Test` 로 규칙 사례 15개 + 실제 데이터 결정성 2개를 확인한다.

환경 점검·엑셀 검증·C# 테스트·반복 전투는 실행 확인을 마쳤습니다. MCP는 SDK 설치 및 실제 연결 검증이 남아 있고, Unity 내부 검증은 라이선스 초기화 단계에서 완료되지 않았습니다.

C# 테스트 20개 통과반복 전투·재현 확인MCP 연결 미검증Unity 검증 미완료

명령은 프로젝트 폴더에서 PowerShell로 실행합니다. 필요한 단계의 코드를 복사해 사용할 수 있습니다.

구성

하네스는 AI가 사용하는 실행·검증 환경이고, MCP는 그 기능을 AI 앱에 제공하는 연결 방식이다. 두 계층이 harness.py를 공유하므로 MCP가 없어도 모든 검증과 반복 전투를 명령줄에서 사용할 수 있다. LLM API 키나 별도 유료 API는 이 도구를 실행하는 데 필요하지 않다.

파일역할
harness.py환경·엑셀 검증·C# 검사·반복 전투·보고서
CoreRunner실제 Core 소스를 직접 컴파일하는 .NET 10 실행기

artifacts/실행별 JSON 결과·검증 staging·Unity 로그(버전 관리 제외)

CoreRunner는 전투 공식을 복제하지 않는다. Unity에서 사용하는 Core/*.cs를 컴파일한다. 그러나 .NET에서 통과했다는 사실은 Unity Mono/IL2CPP·Runtime·화면까지 검증했다는 뜻이 아니다.

1단계: 환경

프로젝트 루트에서 실행한다. 다른 위치에서는 스크립트 절대 경로를 사용해도 된다.

python Tools/AIHarness/harness.py doctor

필수: Python(openpyxl 포함), .NET 10 SDK. MCP 연결에는 추가로 mcp SDK가 필요하다. 현재 .NET 10을 사용한다. Unity 자체의 타깃 프레임워크를 변경하지 않는다. NuGet 외부 소스는 비워 두었다. 이 C# 도구에는 외부 NuGet 패키지가 필요 없으며 로컬 SDK 참조 팩을 사용한다. Unity 위치는 ProjectVersion.txt의 버전으로 탐색한다. 다른 위치면 다음 환경변수를 지정한다.

$env:ARPG_UNITY_EDITOR = 'C:/Program Files/Unity/Hub/Editor/6000.6.7f1/Editor/Unity.exe'

doctor의 패키지 존재 여부는 해당 기능의 실행 성공과 구별한다. PNG 렌더러는 선택 사항이다.

2단계: 검증·실험

python Tools/AIHarness/harness.py validate
python Tools/AIHarness/harness.py test
python Tools/AIHarness/harness.py scenarios
python Tools/AIHarness/harness.py run --scenario 'guardian vs all' --runs 10 --seed 12345
python Tools/AIHarness/harness.py character --query '가디언'
python Tools/AIHarness/harness.py check
  • validate: 기존 변환기를 staging에 실행한다. 원본 엑셀과 런타임 JSON을 수정하지 않는다.
  • 엑셀 수식은 재계산하지 않는다. Excel에서 계산·저장한 캐시가 필요하다.
  • test: 합성 규칙 테스트와 실제 데이터 결정성·구독자 독립성 테스트를 함께 실행한다.
  • run: 고정 masterSeed에서 기존 BatchCoordinator의 회차별 시드 생성과 전투 코어를 그대로 사용한다.
  • check: 환경·엑셀·C# 검증을 실행하고 종합 결과를 저장한다. Unity 검사는 별도다.
  • 원본 해시와 배포 manifest가 다르면 fresh=false로 표시한다. check는 이 경우 실패한다.
  • 기존 비활성 스킬·경고는 변환기 정책대로 보고하며, 경고가 있다는 이유만으로 실패시키지 않는다.
  • 보고서는 UTC 시각·실제 코드/JSON 입력 해시·시나리오 해시·시드를 기록한다.
  • 종료 코드 0=성공, 1=검증 실패, 2=호출/실행 오류. 출력의 ok와 보고서도 함께 확인한다.
  • 반복 실행은 1~10000회, 실행 프로세스는 180초 제한이다. 시간 초과 결과는 성공으로 취급하지 않는다.
  • 검증용 staging을 실제 런타임에 자동 배포하지 않는다. 정식 갱신은 기존 Excel 변환 메뉴를 사용한다.
  • 같은 작업 폴더에서 빌드·배포와 여러 검증 실행을 동시에 하지 않는다.

Unity 검사는 프로젝트를 열어 둔 Editor를 닫은 뒤 실행한다. 열린 프로젝트를 강제 종료하지 않는다.

python Tools/AIHarness/harness.py unity-test

Unity의 -executeMethod ARPG.EditorTools.HarnessBatch.Verify로 실제 로더와 자체 검사를 호출한다. 대화상자 없이 JSON 결과를 기록하고 Editor 종료 코드로 통과/실패를 돌려준다. 이 검사는 화면·애니메이션·클릭 동작을 검증하지 않는다.

3단계: MCP

공식 SDK v1 API를 사용한다. v2 전환은 별도 작업으로 다룬다.

python -m venv Tools/AIHarness/.venv
Tools/AIHarness/.venv/Scripts/python.exe -m pip install -r Tools/AIHarness/requirements.txt
Tools/AIHarness/.venv/Scripts/python.exe Tools/AIHarness/smoke_mcp.py

이 환경에서 venv의 ensurepip가 실패하면, pip가 있는 기본 Python에서 아래 명령으로 해당 venv에 설치할 수 있다.

python -m pip --python Tools/AIHarness/.venv/Scripts/python.exe install -r Tools/AIHarness/requirements.txt

연결할 AI 앱의 로컬 stdio MCP 설정에 mcp.config.example.json의 서버 항목을 등록한다. 이 JSON은 mcpServers 형식을 받는 클라이언트용 예시이며 모든 앱의 설정 파일 형식이 같지는 않다. Codex용 TOML 예시는 mcp.codex.example.toml이다. 기존 사용자 설정을 통째로 덮어쓰지 말고 서버 테이블을 병합한다. 실행 도구는 빌드·시뮬레이션이 필요하므로 클라이언트 도구 제한 시간을 360초로 설정했다. 다른 PC에서는 command와 args를 실제 절대 경로로 변경한다. HTTP 원격 MCP만 받는 앱에는 이 stdio 구성을 그대로 등록할 수 없다. ChatGPT의 현재 세션에 등록되었다고 가정하지 않는다. 클라이언트의 도구 목록에 나타나고 실제 호출에 성공해야 연결 완료다.

MCP 도구기능
check_environment환경·데이터 최신 여부
scenarios시나리오 ID 목록
character캐릭터 검색·이름이 붙은 능력치
validate_excelstaging 데이터 검증
test_coreC# 테스트 실행
run_battles지정 시나리오 반복 실행
execution_report이전 보고서 조회

MCP 서버는 로컬 stdio만 사용한다. 원본 엑셀 수정·임의 셸 명령·임의 파일 경로 실행 기능은 제공하지 않는다. 도구는 보고서를 생성하고 C# 실행기를 빌드하므로 완전한 읽기 전용은 아니다. 여러 클라이언트의 동시 빌드는 아직 지원 범위가 아니다.

4단계: 이어서 확장

  1. 현재 클라이언트에서 로컬 MCP 지원 여부 확인 후 등록·호출 검증.
  2. 기준 시나리오별 회귀 결과 저장과 변경 전후 비교 도구 추가.
  3. 통계·이벤트 CSV 조회를 추가해 기절/가드/자원 부족의 원인 분석 지원.
  4. 데이터 변경 후보를 별도 복사본에 적용하고 비교하는 실험 기능 추가.
  5. 마지막으로 목표 승률·전투 시간에 대한 자동 수치 탐색 추가.

먼저 재현·검증이 가능한 실행 경로를 갖추고, 그 위에 자동 분석을 확장한다.

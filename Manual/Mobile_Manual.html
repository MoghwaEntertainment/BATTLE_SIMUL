엑셀 기획 테이블의 캐릭터·스킬·AI 로 전투를 돌려 보고, 화면으로 확인하거나 수백 판을 빠르게 돌려 승률을 내는 Unity 도구입니다.

기준: 2026-11-01 · Unity 6000.6 · 규칙 rules 2026.11.01-r2 · 화면 오른쪽 위 가− / 가+ 로 이 문서의 글자 크기를 바꿀 수 있습니다.

1빠른 시작

1
프로젝트 열기
Unity Hub 에서 Unity_Project/BalanceMaker 를 엽니다.
2
Play
Project 창에서 Assets/Scenes/SampleScene 을 더블클릭하고 위쪽 ▶ Play 를 누릅니다.
3
전투 시작
왼쪽 패널에서 시나리오를 고르고 ▶ 시작/재개 를 누릅니다.
알아두면 좋은 점 시뮬레이터 화면은 Play 를 누르면 저절로 만들어집니다. 장면에 따로 무언가를 배치할 필요가 없습니다. 전용 장면이 필요하면 메뉴 ARPG › 1. Simulator 장면 만들기 로 Assets/ARPG/Scenes/Simulator.unity 를 만들어 쓰세요.
처음 한 번 확인 Play 를 눌렀는데 아래쪽 Console 창에 빨간 오류가 있으면 실행되지 않습니다. 오류 문구를 그대로 복사해 전달하면 고칠 수 있습니다.

2화면 구성

Play 중인 Game 화면은 다섯 부분으로 나뉩니다. 번호는 아래 표와 같습니다.

화면 구성 예시(숫자·이름은 예시입니다). 실제 글자와 버튼은 글자 크기 설정에 따라 커집니다.
번호부분하는 일
1왼쪽 패널모든 조작이 여기 있습니다. 데이터 읽기, 시나리오 편집, 관찰 모드/고속 반복 전환, 재생 조작, 표시 옵션, Self Test.
2상단 바지금 회차, tick(1/30초 단위 시간), 경과 시간, 배속, 일시정지 여부, 결과를 보여 줍니다.
3전장캐릭터(캡슐)들이 싸우는 곳. 마우스로 카메라를 움직이고, 캐릭터를 왼쪽 클릭하면 선택됩니다.
4정보창선택한 캐릭터의 HP·FP·스태미나 실제 값, 강인도, 상태이상 게이지, 현재 행동과 진행, AI 가 고른 행 번호, 대상과 거리, 쿨다운, 누적 통계.
5로그창최근 전투 사건(행동 시작, 명중, 가드, 상태이상 등)이 아래로 쌓이며 최신 줄이 맨 아래에 나옵니다. 맨 아래를 보고 있으면 새 줄을 따라 내려가고, 위로 올려 읽는 동안에는 멈춥니다. 그때 나타나는 ▼ 최신으로 를 누르면 다시 맨 아래로 갑니다.

3시나리오 만들기

시나리오는 “누가 누구와, 몇 명씩, 어떤 조건으로 싸우는가”를 정한 설정입니다. 화면에서 만드는 방법과 파일을 직접 고치는 방법이 있습니다.

화면에서 만들기 (Play 중)

  1. 시나리오 고르기왼쪽 패널 ■ 시나리오 의 ◀ ▶ 로 저장된 시나리오를 넘깁니다. 예시 5개가 들어 있습니다.
  2. 캐릭터 넣기팀 줄의 + 추가 를 누르면 선택 창이 열립니다. 이름이나 ID 로 검색하고, PC/몬스터 체크로 거른 뒤 목록에서 누르면 그 팀에 들어갑니다. 이미 있는 캐릭터를 또 누르면 인원이 1 늘어납니다.
  3. 인원 조정캐릭터 줄의 - + 로 마릿수를 바꾸고, x 로 뺍니다.
  4. 조건 입력masterSeed, 반복, 제한(초), 거리를 입력합니다(아래 표).
  5. 이름 정하고 저장이름 칸에 이름을 쓰고 저장. 같은 이름이면 덮어쓰고, 이름을 바꿔 저장하면 새 시나리오가 됩니다.
칸뜻
masterSeed난수의 기준값. 같은 값이면 결과도 항상 같습니다. 다른 결과를 보고 싶으면 값을 바꾸거나 다음 회차로 넘어가세요.
반복고속 반복에서 돌릴 판 수. 자동 다음 회차에서는 여기까지 진행합니다.
제한(초)이 시간이 지나도 승부가 안 나면 시간 초과로 끝납니다.
거리두 팀이 처음 떨어져 서는 거리(m).
바로 반영 화면에서 바꾼 내용은 관찰 모드에 바로 적용되어 회차 1부터 다시 준비됩니다. 단, 저장 을 누르기 전까지는 파일에 남지 않습니다.

4관찰 모드 (한 판씩 보기)

왼쪽 패널 가운데의 관찰 모드 를 고른 상태입니다. 한 판을 화면으로 재생하며 행동과 수치를 확인합니다.

버튼 · 옵션하는 일
▶ 시작/재개 ⏸ 정지재생과 일시정지. 키보드 Space 도 같습니다.
1 tick1/30초만 진행하고 멈춥니다. 한 동작씩 뜯어볼 때. 키보드 .
재시작(같은 seed)지금 회차를 처음부터. 같은 결과가 다시 나옵니다.
다음 회차다음 난수로 새 판을 준비합니다.
자동 다음 회차판이 끝나면 다음 판을 저절로 시작합니다(5장).
배속0.5x · 1x · 2x · 4x · 8x. 너무 빨라 처리가 못 따라가면 상단 바에 처리 지연이 뜹니다.
Console / 화면 로그Unity Console 과 로그창에 얼마나 자세히 남길지. 끔 · 핵심 · 상세.
이벤트 CSV 기록켜 두면 판마다 사건 기록 파일을 남깁니다(8장).
로그창화면 아래 로그창 보이기/숨기기. 최신 줄이 맨 아래에 쌓입니다.
판정 범위 표시공격 판정 원, 선택 캐릭터의 거리 원과 대상 선(7장).
공격 이펙트(막대·착탄)공격이 맞을 때 날아가는 막대와 착탄 표시 켜기/끄기.

캐릭터 목록 버튼패널 아래쪽 A1, B1 같은 버튼을 누르면 그 캐릭터가 선택됩니다.
한 캐릭터만 따라가기 캐릭터를 왼쪽 클릭으로 선택한 뒤 F (또는 정보창의 카메라 추적(F)) 를 누르면 카메라가 그 캐릭터를 따라갑니다. 가운데 버튼으로 끌거나 WASD 로 카메라를 옮기면 추적이 풀립니다.

5자동 다음 회차

관찰 모드에서 자동 다음 회차를 체크하면, 판이 끝날 때마다 다음 판이 저절로 이어집니다. 화면으로 보면서 여러 판을 계속 돌릴 때 씁니다.

  1. 체크하기☐ 자동 다음 회차 (회차 N까지) 를 체크합니다. 멈춰 있던 판은 바로 재생됩니다.
  2. 자동으로 이어짐판이 끝나면 결과를 볼 수 있게 약 1.2초 쉬었다가(배속이 높으면 그만큼 짧게) 다음 회차를 시작합니다.
  3. 끝나는 때회차 번호가 시나리오의 반복 값에 닿으면 멈춥니다. 중간에 멈추려면 체크를 풉니다.
  • 체크 아래에 누적 결과가 표시됩니다. 예: 12판: 아군 승 8 / 적군 승 3 / 무승부·시간초과 1
  • 카메라 위치와 추적 중인 캐릭터는 다음 판에도 그대로 유지됩니다.
  • 시나리오를 바꾸면 누적 결과가 0 부터 다시 셉니다.
파일이 많이 생길 수 있어요 이벤트 CSV 기록이 켜져 있으면 판마다 기록 파일이 생깁니다. 많이 돌릴 때 필요 없으면 꺼 두세요.
승률만 빨리 알고 싶다면 화면을 볼 필요가 없으면 고속 반복이 훨씬 빠릅니다. 같은 masterSeed 면 고속 반복과 관찰 모드의 회차별 결과가 같습니다.

6고속 반복 (승률 내기)

캐릭터를 화면에 그리지 않고 시나리오를 반복 횟수만큼 빠르게 돌려 승률과 통계를 냅니다. “반복 100” 은 이 모드에서 100판을 뜻합니다.

  1. 모드 바꾸기왼쪽 패널 가운데 고속 반복(비시각) 을 누릅니다.
  2. 옵션 고르기 이벤트 CSV: 없음(가장 빠름) · 처음 N회(앞의 몇 판만 상세 기록) · 전체(모든 판, 파일이 큼).
    프레임 예산: 한 화면 프레임에 계산에 쓰는 시간(4~60ms). 크게 하면 빨리 끝나지만 화면 반응이 둔해집니다.
  3. 실행실행 을 누르면 진행 막대가 차오릅니다. 중간에 취소 하면 그때까지의 결과가 부분 결과로 저장됩니다.
  4. 결과 보기패널에 요약이 나오고, 결과 폴더 열기 로 CSV 파일을 엽니다.

캐릭터 색

  • 파랑: 팀 0(아군)
  • 빨강: 팀 1(적군)
  • 초록·노랑: 팀 2·3
  • 흰색 깜빡임: 맞음
  • 청록: 회피 무적 시간
  • 주황빛: 경직(강인도 붕괴)
  • 하늘빛: 빙결(이동·공격·구르기 느려짐)
  • 보랏빛: 중독
  • 머리 위 노란 고리 회전: 기절
  • 회색으로 쓰러짐: 사망

머리 위 막대와 바닥 고리

  • HP · FP · 스태미나. 회색 막대는 쓰지 않는 자원(몬스터의 FP·스태미나)입니다.
  • 스태미나가 0 아래(음수)로 내려가면 막대는 0 이고 배경이 붉게 바뀝니다. 실제 음수 값은 정보창·로그·CSV 에 남습니다.
  • 바닥 고리는 팀 색. 선택한 캐릭터는 노란 고리로 커집니다.

동작

동작보이는 모습
공격준비 동작에서 몸을 살짝 뒤로 젖혔다가, 타격 직전 앞으로 숙이며 한 발 내딛고, 타격마다 조금 더 숙입니다. 무기는 옆으로 휘두르며, 공격 중에는 스킬 피해 타입에 따라 모양이 바뀝니다(아래 공격 이펙트 표).
구르기(회피)몸이 앞뒤로 한 바퀴(360°) 굴러갑니다. 상대 쪽으로 피하면 앞구르기, 뒤로 피하면 뒷구르기. 구르는 동안 무기는 숨기고, 무적 시간에는 청록색입니다.
가드몸 앞에 청록 방패가 나타납니다. 막으면 방패가 흰색으로 깜빡입니다.
경직 · 기절몸이 뒤로 기울고 색이 바뀝니다(위 색 설명). 경직(1초) 중에는 맞아도 HP 만 줄고 강인도는 깎이지 않아 다시 경직되지 않습니다.

공격 이펙트 (막대·착탄)

공격 판정이 나면 공격자의 무기 높이에서 대상 몸통으로 투사체가 날아가고, 닿는 순간 착탄 구체가 생기며 대상이 깜빡입니다. 판정에는 영향을 주지 않는 화면 표시입니다.

투사체와 공격 중 손에 든 무기의 모양은 스킬의 Damage_Type 으로 정해집니다. 타입이 여러 개면 앞에 적힌 타입을 따릅니다(예: SLASH, MAGIC → 막대).

STRIKE막대 끝에 사면체 머리 — 망치
MAGIC하늘색 구체
FIRE빨간 구체

LIGHTNING진한 노란 막대(조금 굵음)

막대·화살·망치의 색은 아래처럼 결과를 나타냅니다. 구체와 번개 막대는 속성 색을 유지하고, 빗나가면 회색이 섞입니다. 결과는 착탄 구체 색으로도 구별됩니다.

  • 노랑: 명중
  • 청록: 가드에 막힘
  • 옅은 하늘: 회피 무적으로 무효
  • 회색: 빗나감(앞으로 날아가 사라짐)

판정 범위 표시 (켰을 때)

  • 노란 원: 공격이 맞을 범위(준비 동작 중). 빨간 원: 곧 타격.
  • 선택한 캐릭터 주변의 옅은 원 두 개: 안쪽 2.5m(근접), 바깥 6m(중거리). 그보다 멀면 AI 조건의 far 입니다.
  • 선택한 캐릭터에서 대상으로 이어지는 노란 선: 지금 노리는 대상.

13명령줄 실행 (고급)

Unity 로 빌드한 실행 파일을 화면 없이 돌려 대량 결과를 낼 수 있습니다. 평소에는 고속 반복으로 충분합니다.

BalanceMaker.exe -batchmode -nographics -logFile batch.log -arpgBatch ^
  --scenario 01_근접1대1_검사37_vs_기사단장37 --runs 1000 --seed 12345 ^
  --output results --events first:3
인자뜻
--scenario시나리오 이름 또는 파일 경로(필수)
--runs판 수(없으면 시나리오의 반복 값)
--seedmasterSeed 덮어쓰기
--maxsec제한 시간(초) 덮어쓰기
--output결과 폴더(없으면 Exports 폴더)
--eventsnone(기본) · first:N · all

끝날 때 돌려주는 값: 0 성공, 2 인자·입력 오류, 3 실행 오류.

14문제 해결 · 자주 묻는 질문

Play 를 눌렀는데 시뮬레이터 화면이 안 나와요.
열린 장면이 SampleScene 또는 Simulator 인지 확인하세요. 자동 생성은 이 두 장면에서만 됩니다. Console 에 빨간 오류가 있으면 먼저 해결해야 합니다.
왼쪽 위에 “데이터 로드 실패” 가 떠요.
JSON 데이터가 없거나 깨진 경우입니다. 메뉴 ARPG › 2. 엑셀 → JSON 변환 실행 을 한 번 실행한 뒤 데이터 다시 읽기.
“시나리오 오류” 가 떠서 시작이 안 돼요.
대표적인 원인은 ① 데이터에 없는 캐릭터 ID ② 검증에서 비활성 처리된 캐릭터 ③ 두 팀 이상에 1명 이상 배치되지 않음 ④ 반복이 0 이하 ⑤ 제한 시간이 0 이하 입니다. 문구에 적힌 내용을 고치세요.
몇 번을 돌려도 결과가 똑같아요.
정상입니다. 같은 masterSeed 와 같은 회차는 항상 같은 결과가 나옵니다(재현을 위해). 다음 회차 로 넘기거나 masterSeed 를 바꾸세요.
반복에 100 을 넣었는데 한 판만 돌고 끝나요.
관찰 모드는 한 판씩입니다. 화면으로 계속 보려면 자동 다음 회차, 승률만 필요하면 고속 반복을 쓰세요.
엑셀을 고쳤는데 반영이 안 돼요.
① 엑셀에서 저장했는지 ② 변환 메뉴를 실행했는지 ③ Play 중이면 데이터 다시 읽기를 눌렀는지 ④ 검증 보고서에 해당 행 오류가 없는지 확인하세요.
화면이 끊기거나 “처리 지연” 이 떠요.
배속을 낮추고, 로그를 “끔” 으로, 판정 범위 표시·공격 이펙트를 꺼 보세요. 많은 판을 돌릴 때는 고속 반복을 쓰세요.
Unity 를 켜 둔 채로 코드를 수정해도 되나요?
됩니다. 단 Play 를 멈춘 상태에서 수정하세요. 수정 후 Unity 창을 클릭하면 자동으로 다시 컴파일되고, 오른쪽 아래 진행 표시가 끝나면 Play 하면 됩니다.
결과 CSV 를 엑셀로 열면 한글이 깨져요.
시뮬레이터가 만든 CSV 는 엑셀용 표시(BOM)를 넣어 저장하므로 보통 깨지지 않습니다. 다른 프로그램에서 다시 저장한 파일이라면 원본을 다시 여세요.

환경 점검·엑셀 검증·C# 테스트·반복 전투는 실행 확인을 마쳤습니다. MCP는 SDK 설치 및 실제 연결 검증이 남아 있고, Unity 내부 검증은 라이선스 초기화 단계에서 완료되지 않았습니다.

C# 테스트 20개 통과반복 전투·재현 확인MCP 연결 미검증Unity 검증 미완료

명령은 프로젝트 폴더에서 PowerShell로 실행합니다. 필요한 단계의 코드를 복사해 사용할 수 있습니다.

구성

하네스는 AI가 사용하는 실행·검증 환경이고, MCP는 그 기능을 AI 앱에 제공하는 연결 방식이다. 두 계층이 harness.py를 공유하므로 MCP가 없어도 모든 검증과 반복 전투를 명령줄에서 사용할 수 있다. LLM API 키나 별도 유료 API는 이 도구를 실행하는 데 필요하지 않다.

파일역할
harness.py환경·엑셀 검증·C# 검사·반복 전투·보고서
CoreRunner실제 Core 소스를 직접 컴파일하는 .NET 10 실행기
mcp_server.py공식 Python SDK v1의 FastMCP stdio 연결
smoke_mcp.pyMCP 초기화·도구 목록·실제 호출 검사
artifacts/실행별 JSON 결과·검증 staging·Unity 로그(버전 관리 제외)
Unity_Plan/08_AI하네스_MCP_구현기록.md완료 상태, 장애, 다음 명령

CoreRunner는 전투 공식을 복제하지 않는다. Unity에서 사용하는 Core/*.cs를 컴파일한다. 그러나 .NET에서 통과했다는 사실은 Unity Mono/IL2CPP·Runtime·화면까지 검증했다는 뜻이 아니다.

1단계: 환경

프로젝트 루트에서 실행한다. 다른 위치에서는 스크립트 절대 경로를 사용해도 된다.

python Tools/AIHarness/harness.py doctor

필수: Python(openpyxl 포함), .NET 10 SDK. MCP 연결에는 추가로 mcp SDK가 필요하다. 현재 .NET 10을 사용한다. Unity 자체의 타깃 프레임워크를 변경하지 않는다. NuGet 외부 소스는 비워 두었다. 이 C# 도구에는 외부 NuGet 패키지가 필요 없으며 로컬 SDK 참조 팩을 사용한다. Unity 위치는 ProjectVersion.txt의 버전으로 탐색한다. 다른 위치면 다음 환경변수를 지정한다.

$env:ARPG_UNITY_EDITOR = 'C:/Program Files/Unity/Hub/Editor/6000.6.7f1/Editor/Unity.exe'

doctor의 패키지 존재 여부는 해당 기능의 실행 성공과 구별한다. PNG 렌더러는 선택 사항이다.

2단계: 검증·실험

python Tools/AIHarness/harness.py validate
python Tools/AIHarness/harness.py test
python Tools/AIHarness/harness.py scenarios
python Tools/AIHarness/harness.py run --scenario 'guardian vs all' --runs 10 --seed 12345
python Tools/AIHarness/harness.py character --query '가디언'
python Tools/AIHarness/harness.py check
  • validate: 기존 변환기를 staging에 실행한다. 원본 엑셀과 런타임 JSON을 수정하지 않는다.
  • 엑셀 수식은 재계산하지 않는다. Excel에서 계산·저장한 캐시가 필요하다.
  • test: 합성 규칙 테스트와 실제 데이터 결정성·구독자 독립성 테스트를 함께 실행한다.
  • run: 고정 masterSeed에서 기존 BatchCoordinator의 회차별 시드 생성과 전투 코어를 그대로 사용한다.
  • check: 환경·엑셀·C# 검증을 실행하고 종합 결과를 저장한다. Unity 검사는 별도다.
  • 원본 해시와 배포 manifest가 다르면 fresh=false로 표시한다. check는 이 경우 실패한다.
  • 기존 비활성 스킬·경고는 변환기 정책대로 보고하며, 경고가 있다는 이유만으로 실패시키지 않는다.
  • 보고서는 UTC 시각·실제 코드/JSON 입력 해시·시나리오 해시·시드를 기록한다.
  • 종료 코드 0=성공, 1=검증 실패, 2=호출/실행 오류. 출력의 ok와 보고서도 함께 확인한다.
  • 반복 실행은 1~10000회, 실행 프로세스는 180초 제한이다. 시간 초과 결과는 성공으로 취급하지 않는다.
  • 검증용 staging을 실제 런타임에 자동 배포하지 않는다. 정식 갱신은 기존 Excel 변환 메뉴를 사용한다.
  • 같은 작업 폴더에서 빌드·배포와 여러 검증 실행을 동시에 하지 않는다.

Unity 검사는 프로젝트를 열어 둔 Editor를 닫은 뒤 실행한다. 열린 프로젝트를 강제 종료하지 않는다.

python Tools/AIHarness/harness.py unity-test

Unity의 -executeMethod ARPG.EditorTools.HarnessBatch.Verify로 실제 로더와 자체 검사를 호출한다. 대화상자 없이 JSON 결과를 기록하고 Editor 종료 코드로 통과/실패를 돌려준다. 이 검사는 화면·애니메이션·클릭 동작을 검증하지 않는다.

3단계: MCP

공식 SDK v1 API를 사용한다. v2 전환은 별도 작업으로 다룬다.

python -m venv Tools/AIHarness/.venv
Tools/AIHarness/.venv/Scripts/python.exe -m pip install -r Tools/AIHarness/requirements.txt
Tools/AIHarness/.venv/Scripts/python.exe Tools/AIHarness/smoke_mcp.py

이 환경에서 venv의 ensurepip가 실패하면, pip가 있는 기본 Python에서 아래 명령으로 해당 venv에 설치할 수 있다.

python -m pip --python Tools/AIHarness/.venv/Scripts/python.exe install -r Tools/AIHarness/requirements.txt

연결할 AI 앱의 로컬 stdio MCP 설정에 mcp.config.example.json의 서버 항목을 등록한다. 이 JSON은 mcpServers 형식을 받는 클라이언트용 예시이며 모든 앱의 설정 파일 형식이 같지는 않다. Codex용 TOML 예시는 mcp.codex.example.toml이다. 기존 사용자 설정을 통째로 덮어쓰지 말고 서버 테이블을 병합한다. 실행 도구는 빌드·시뮬레이션이 필요하므로 클라이언트 도구 제한 시간을 360초로 설정했다. 다른 PC에서는 command와 args를 실제 절대 경로로 변경한다. HTTP 원격 MCP만 받는 앱에는 이 stdio 구성을 그대로 등록할 수 없다. ChatGPT의 현재 세션에 등록되었다고 가정하지 않는다. 클라이언트의 도구 목록에 나타나고 실제 호출에 성공해야 연결 완료다.

MCP 도구기능
check_environment환경·데이터 최신 여부
scenarios시나리오 ID 목록
character캐릭터 검색·이름이 붙은 능력치
validate_excelstaging 데이터 검증
test_coreC# 테스트 실행
run_battles지정 시나리오 반복 실행
execution_report이전 보고서 조회

MCP 서버는 로컬 stdio만 사용한다. 원본 엑셀 수정·임의 셸 명령·임의 파일 경로 실행 기능은 제공하지 않는다. 도구는 보고서를 생성하고 C# 실행기를 빌드하므로 완전한 읽기 전용은 아니다. 여러 클라이언트의 동시 빌드는 아직 지원 범위가 아니다.

4단계: 이어서 확장

  1. 현재 클라이언트에서 로컬 MCP 지원 여부 확인 후 등록·호출 검증.
  2. 기준 시나리오별 회귀 결과 저장과 변경 전후 비교 도구 추가.
  3. 통계·이벤트 CSV 조회를 추가해 기절/가드/자원 부족의 원인 분석 지원.
  4. 데이터 변경 후보를 별도 복사본에 적용하고 비교하는 실험 기능 추가.
  5. 마지막으로 목표 승률·전투 시간에 대한 자동 수치 탐색 추가.

먼저 재현·검증이 가능한 실행 경로를 갖추고, 그 위에 자동 분석을 확장한다.
